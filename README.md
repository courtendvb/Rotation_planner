# Rotation Planner

バレーボール(一般の6人制)のローテーションのマッチアップを、DataVolley(.dvw)の実績から確認・研究し、最適なスタートローテーションを探すための、ローカルで動く R + Shiny アプリです。

## 起動方法

必要なパッケージ:`shiny`、`DT`(テストには `testthat`)

```r
install.packages(c("shiny", "DT"))
```

**インストールせずに起動する**(このフォルダを作業ディレクトリにして実行)

```r
source("run.R")
```

**パッケージとしてインストールして起動する**

```r
# install.packages("remotes")
remotes::install_local("path/to/Rotation_planner")
shiny::runApp(rotationplanner::run_app())
```

データ(チーム、立ち位置、データタブの設定)は自動で RDS ファイルに保存されます。保存先は `tools::R_user_dir("rotationplanner", "data")` です。変える場合は `run_app(data_dir = "~/rotation-data")` のように指定します。

## 画面

| タブ | できること |
|---|---|
| チーム | 自チームと相手チームの選手(背番号・名前・役割)、スタートの並び、リベロを登録 |
| ローテーション | 自チームと相手のスタート、最初のサーブを設定すると、そのセットで起きる12通りの対面を1画面に表示。上段は自チームサーブ時(ブレイクフェイズ)の6ローテーション、下段は自チームレセプション時(サイドアウトフェイズ)の6ローテーション。各コートに、その対面の実績(取った数/ラリー数)と見込みを表示し、レシーブ側(サイドアウト側)にはレセプション位置から攻撃位置への移動を矢印で示す。初期表示は役割から自動で作った標準のフォーメーション(サーブ側はサーバーがエンドラインの外)で、選手をドラッグすると両チームとも立ち位置を変更・保存できる |
| マッチアップ | 対面別の実績(自チームのローテーション × 相手のローテーションの 6×6、レセプション時とサーブ時)、スタートの組み合わせごとのセット取得確率、おすすめのスタート、各組み合わせで起きる12通りの対面の詳細 |
| データ | DataVolley の .dvw を読み込み、両チームのメンバー(チーム名、背番号・名前・役割、スタートの並び、リベロ)を取り込む。ファイルのパスを指定すると、試合中に DataVolley が保存するたびに自動で読み直し、対面別の実績をリアルタイムで各タブに反映する |

## 考え方

- サイドアウトのたびに、サーブ権を得たチームだけが1つ回ります。そのため両チームの回転数の差は常に 0 か 1 です。
- したがって **1セットの間に起きる対面は、両チームのスタートローテーションと最初のサーブ権だけで決まります**(12通り。選手交代では変わりません)。
- マッチアップを最適化するとは、相手のスタートを予想し、自チームのスタートを選ぶことです。

### 実績と見込み

見込み(自チームがそのラリーを取る確率)は、.dvw の実績だけから計算します(`rally_prob_from_stats()`)。

1. 対面(自チームのローテ × 相手のローテ × サーブ権)ごとに、ラリー数と自チームが取った数を数える(`matchup_stats()`)
2. 実績の少ない対面は、ローテーション単位の実績(自チームのそのローテのサイドアウト率・ブレイク率と、相手のそのローテの率の平均)に寄せる
3. それも少なければチーム全体の実績に、実績がまったくなければ一般的な値(レシーブ側のサイドアウト率 60%)に寄せる

どれだけ寄せるかはデータタブの「実績の少ない対面の補正」(既定 10 本で半々)で変えられます。

### レセプションの型と、攻撃に入る動き

並びが標準の 5-1(セッターから S → OH → MB → OP → OH → MB の順)のときは、指導者のレクチャー図をもとにした型(`R/reception.R` の `RECEPTION_TEMPLATES`)を使います。セッターの位置(S1〜S6)ごとに、次を持っています。

- レセプションの立ち位置(S・OP・前衛 MB・前衛 OH・後衛 OH・リベロ)
- 攻撃に入る動きの経路(通過点と終点)。セッターとリベロは矢印なし
- 終点は、前衛アタッカーはネット際(0.5m)、後衛アタッカー(パイプ・バックライト)はアタックラインのすぐ後ろ(3.2m)にそろえる

S1 は別パターン「OPレフト」も選べます(ローテーションタブの「自チームの S1」「相手の S1」、チームごとに保存)。OP がレフトに残って攻撃し、前衛 OH がライトでレシーブしてライトから攻撃、後衛 OH は左でレシーブしてパイプに入ります。別パターンを追加するときは `RECEPTION_VARIANTS` と `RECEPTION_VARIANT_CHOICES` に足します。ドラッグで変えた立ち位置はパターンごとに別に保存されます。

矢印は今の立ち位置から描くので、選手をドラッグすると始点も動きます。型を直すときは `RECEPTION_TEMPLATES` の座標(各チームの自コート視点、x: 左→右 0〜9m、y: ネット→エンドライン 0〜9m)を書き換えます。

標準の 5-1 でない並びでは、役割から隊形を自動で作り(`generic_reception()`)、攻撃位置へまっすぐ向かう矢印を描きます。

### コート図

自チームのエンドラインの後ろ上方から見た遠近法(奥ほど狭い台形)で描きます。奥の幅は `PERSPECTIVE_RATIO`、奥行きの縮みは `PERSPECTIVE_DEPTH`(`R/court.R`)で調整できます。マーカーの大きさは遠近で変えません。

### マーカーの色

セッター=黒、アウトサイド=青、ミドル=緑、オポジット=赤、リベロ=紫。

マッチアップタブのコート図も、レシーブ側はこのフォーメーション(編集した場合はその立ち位置)で表示します。

### DataVolley(.dvw)の読み込み

`read_dvw()` は外部パッケージを使わずに .dvw を読みます(UTF-8 / Shift_JIS / Windows-1252 を自動判定)。

- 選手:背番号、姓・名、リベロ印、役割コード(1=L, 2=OH, 3=OP, 4=MB, 5=S)
- 役割コードが空の選手は、セッターの宣言(`*P04` など)、プレー内容(トス・レセプション・クイック)、5-1 の並び(セッターの対角=OP、MB の対角=MB)から推定
- スタートの並び:指定したセットの最初の記録の P1〜P6
- 実績:サーブの記録と得点の記録からラリーを組み立て、サーブ時の両チームのセッター位置(S1〜S6)で対面を決めて集計
- メンバーを読み込むと、ドラッグで変えた立ち位置は標準のフォーメーションに戻る

### セット取得確率

`(自チームのローテ, 相手のローテ, サーブ権)` の72状態のマルコフ連鎖として、後ろ向きに厳密に計算します(`set_win_all_states`)。デュースは連立方程式で解きます。

## 構成

```
R/
  rotation.R    ローテーション、リベロの入れ替わり、スイッチ後の配置
  placement.R   立ち位置の基本形
  formation.R   既定のフォーメーション、型が使えない並びの自動の隊形と矢印
  reception.R   レセプションの型(5-1、レクチャー図)と攻撃に入る動きの経路
  matchup.R     1セットで起きる12通りの対面
  stats.R       対面別の実績と、そこからの見込み
  simulate.R    セット取得確率(マルコフ連鎖)、スタートの順位づけ
  dvw.R         DataVolley(.dvw)の読み込み、役割の推定、実績の集計
  court.R       コート図(SVG、遠近法の台形)
  mod_*.R       Shiny モジュール(roster / rotation / matchup / data)
  app.R         アプリ本体と run_app()
  storage.R     RDS への自動保存
inst/app/www/   ドラッグ操作の JavaScript、CSS
tests/testthat/ テスト
```

中心のロジック(`rotation.R`〜`stats.R`、`dvw.R`)は Shiny に依存しない純粋な関数です。画面は Shiny モジュールに分けてあるので、既存のアプリに組み込めます。

```r
# 既存のアプリにローテーションの12面ボードを組み込む例
# UI 側(コート図と操作用の CSS / JavaScript も読み込む)
addResourcePath("rp", rotationplanner::app_www_dir())
tags$head(tags$link(rel = "stylesheet", href = "rp/rotationplanner.css"),
          tags$script(src = "rp/rotationplanner.js"))
rotationplanner::mod_rotation_ui("rotation")

# server 側:チームと対面別の実績を渡す
d <- rotationplanner::read_dvw("match.dvw")
teams <- reactiveVal(list(us = rotationplanner::dvw_team(d, "home", "us"),
                          them = rotationplanner::dvw_team(d, "visiting", "them")))
stats <- reactive(rotationplanner::matchup_stats(d$rallies, "home", teams()$us, teams()$them))
rotationplanner::mod_rotation_server("rotation", teams, reactiveVal(list()), stats, reactive(TRUE))
```
